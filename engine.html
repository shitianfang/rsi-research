研究简报 · 引擎主张

供给，不是调度

让自改进系统持续变好的，是"还有新题可做"，不是"题目按顺序由易到难"。这是一次预注册实验的结论，而它否定的正是我们自己原本的假设。

2026-09-16 · rsi-research · experiments/05-intent-escalation

00 / 先说清楚测的是什么

引擎主张有两半，这一轮测了其中一半半

"引擎主张"是说：驱动系统不断变好的动力来自任务生成器持续产出更难的任务。它可以拆成两句独立的话：

  • 供给——任务空间一旦枯竭，改进就停。
  • 调度——"由易到难逐步加深"这个机制本身，是改进得以持续的原因。

这一轮对供给给出了确认，对调度给出了否定。

没有测到的那一层，必须先讲。真正的自改进循环里，出题者本身是一个会进化的策略，与解题者共同演化、互相塑造。本实验的"任务生成器"只是一个深度旋钮，不是学出来的。所以严格地说，这一轮回答的是"难度调度对学习者有没有用"，而不是"共同演化的出题者能否维持开放式改进"。后者仍然没有被检验。

01 / 任务

一个可以无限加深、且深层必须踩着浅层才够得到的任务

要让"课程"有可能有用，任务空间必须有踏脚石：深的做不到，除非浅的已经做到。所以用了一个层级结构——[0,1] 上的分段常数函数，由一棵二叉树定义：每个节点在自己区间内某处分开，左右两边取一高一低两个值。意图就是这棵树上每个节点的朝向（哪边高），由机器写定，因此天然是真值。

要学的技能：把有限的数值范围分配到各层

数值范围是有限的。深层每个格子里的样本更少，要扛住噪声就得分到更大的落差；但每一分给深层的，都是从浅层扣下来的。策略 θ = (第1层落差, …, 第4层落差) 就是这个分配方案，存在一个真实的最优解，而且不显然。关键是：只有当上面几层已经恢复正确时，深层的落差才拿得到反馈——所以随机初始的策略从深层任务里几乎得不到梯度。

02 / 三条臂

主对比不是"渐进 vs 永远简单"，那几乎是同义反复

真正值得问的是：同样的算力，直接拿最难的任务训练，是不是一样好？如果一样好，课程就什么都没买到。

臂做法角色
A 渐进从深度 1 开始，成功率达标就加深一层课程文献的最小准则规则
C 直接一上来就在最深的深度 4 训练主对比：课程到底必不必要
B 浅永远停在深度 1地板：验证任务空间真的会枯竭

三条臂消耗完全相同的评估次数（各 900 次）。最终成绩用一批全新的深度 4 意图测，任何一条臂都没有在这批题上训练过。判据和两个分支在跑之前写死并提交进 git。

03 / 结果

失败分支：课程不是必要的

臂留出深度-4 成绩判定
A 渐进加深0.778 ±0.071—
C 直接上难题0.803 ±0.049不低于 A，数值上还略高
B 永远浅0.674 ±0.047明显落后
  • 主判据 A − C = −0.025（2se 0.034）→ 不显著。等算力下，课程买不到任何东西。
  • 次判据 A − B = +0.104（2se 0.065）→ 显著。任务空间确实会枯竭。
  • 渐进臂 8 个种子里 7 个爬到了最深层，机制本身按设计运转。

A 优于 B，说明任务枯竭是真实的天花板；A 不优于 C，说明解药不是"循序渐进"，而是"手上有难题可做"。合起来：驱动持续改进的是任务供给，不是难度调度。

04 / 变化

把三条臂学到的东西摊开看，零结果立刻有了解释

下面是每条臂最终学到的分配方案（8 个种子平均），以及它和初始值的关系。

臂第1层第2层第3层第4层形状
初始值0.0880.0940.1090.090
A 渐进0.2430.1670.1090.082
C 直接0.2610.1520.0900.071
B 浅0.0880.0940.1090.090

两件事一眼可见。第一，A 和 C 学到的几乎是同一个方案——都把数值范围前重后轻地压向浅层（把落差留给最靠上的分界，因为它错了下面全废）。既然学到的东西一样，成绩一样就不奇怪了：课程只是通往同一个终点的一条较慢的路。

第二，B 的那一行和初始值一个数都没差。它不是学得慢，是一次都没有接受过改进——深度 1 的成绩初始就是 1.000，爬山算法找不到任何可以变好的方向。饱和在这里不是比喻，是一个可以直接读出来的事实。

代价花在哪里：渐进臂的爬升轨迹

种子 0 的记录：第 8 次评估升到深度 2，第 16 次升到深度 3，第 168 次才升到深度 4，此后 732 次都在深度 4。而 C 从第 1 次评估起就在深度 4。多出来的这 168 次不是灾难，但也没换回任何东西——这就是 −0.025 的来源。

臂第1层第2层第3层第4层
A 渐进1.000.890.770.62
C 直接1.000.960.820.63
B 浅0.970.720.650.60

逐层看留出成绩：三条臂在最深的第 4 层几乎打平（0.62 / 0.63 / 0.60），差距全在第 2、3 层。也就是说这个任务的最深层对谁都太难，真正被学到的是中间层——这一点下面还要再说。

05 / 仪器

这一轮差点从坏代码上读数，第四次

正式跑之前有四道仪器门，其中一道抓到了真问题：第 2 层的恢复成绩是 0.38——低于随机的 0.50，而且把探测预算从 64 加到 256 完全不涨（0.625 → 0.622）。系统性低于随机，加上算力轴不单调，是被测对象本身坏掉的典型指纹。

原因在断点检测的统计量：原本用的是"最大化左右均值差的绝对值"，这个量在区间两端取到极大——那里只有两三个样本，均值纯是噪声，样本越多虚假极值越容易出现，所以加预算反而无用。换成二分分割的标准统计量 j(n−j)/n · (mL−mR)² 后，逐层成绩恢复为单调且都在随机水平以上（1.00 / 0.80 / 0.68 / 0.51），算力轴也重新上升。

这是这个项目第四次靠同一条纪律拦下错误结论：读数之前，先证明被测对象真的在工作。前三次分别是——验证器根本没训练、匹配判断恒为假、恢复器在算力轴上反向。每一次，实验都照样输出了一整张看起来合理的结果表。
06 / 边界

这个结论不能被拉伸到哪里去

  • 信号是稠密的，而课程最该发挥作用的场景是稀疏的。仪器门测到随机策略在深度 4 已有 0.705（随机水平 0.5），也就是难题一直在给梯度。课程文献真正针对的是难题完全给不出信号的情形。所以这一轮诚实的表述是：在信号稠密条件下课程买不到东西；对稀疏条件，这一轮不构成检验。
  • 出题者不会进化。本实验的任务生成器是一个深度旋钮，不是学出来的策略。共同演化的出题者能否维持开放式改进，仍然没有被检验——那是引擎主张里最核心、也最难做的一层。
  • 最深层对谁都太难。三条臂在第 4 层几乎打平（0.62/0.63/0.60），差异全在中间层。这说明任务难度的上限设得偏高，真正的对比发生在中段。
  • 短程。900 次评估，不是长周期。"循环会不会最终停下"这个问题，本实验的时间尺度回答不了。

要继续追引擎，下一轮该做的是稀疏信号版本（只用最深一层的全对/全错作为唯一反馈），并且让出题者本身成为一个会进化的策略。那是一次新的独立预注册，不是对这一轮的翻案——这一轮的裁定按预注册成立，不因后续实验而改写。
